FORMATION LAB MOBILE FULLSCREEN ISSUES - DETAILED BREAKDOWN

=== CSS BREAKPOINT INCONSISTENCIES ===

main.css breakpoints (lines 950-1165):
- 1024px: Large tablets
- 768px: Tablets  
- 480px: Small phones
- 359px: Extra small
- 500px height + landscape: Mobile landscape

fullscreen.css breakpoints (lines 192-847):
- 640px: Medium phones (ONLY breakpoint!)
- 768px: Controls width only

PROBLEM: fullscreen.css is missing 480px, 359px, and 280px breakpoints
This means phones under 640px get wrong styling in fullscreen mode.

=== FIXED POSITIONING CASCADE ===

HTML structure:
body
  .flab-app--fullscreen (relative)
    .flab-pitch-wrapper (position: fixed, inset: 0)
      .flab-field (position: relative)
        buttons (position: absolute, right: 12px, top: 12px)

When pitch wrapper is fixed:
- Buttons positioned relative to pitch wrapper
- Pitch wrapper IS the viewport in fullscreen
- Buttons go off-screen on small phones
- Touch events may not register

=== 100VH / 100VW PROBLEM ===

100vh on iOS Safari (iPhone 11):
- Screen height: 812px
- Address bar height: 50px
- Home indicator: 34px
- Available viewport: 812px - 50px - 34px = 728px
- But CSS sees: 100vh = 812px
- Result: Content overflows 84px below visible area

100vw on any phone:
- Includes scrollbar width (varies by device)
- Can be 12-17px wider than actual viewport
- Pitch field overflows horizontally

=== ASPECT RATIO CALCULATION ===

Current formula: width: min(100vw, calc(100vh * (105 / 68)))

On iPhone SE (375 x 667):
- 100vh = 667px (wrong on iOS)
- 667 * (105 / 68) = 1030px
- min(375, 1030) = 375px used
- Height = 375 / 1.544 = 243px
- Unused vertical space: 667 - 243 = 424px (64%!)

On Android phone (360 x 720):
- 100vh = 720px
- 720 * (105 / 68) = 1110px
- min(360, 1110) = 360px used
- Height = 360 / 1.544 = 233px
- Unused: 720 - 233 = 487px (68%!)

The issue: Landscape pitch in portrait phone = wasted space

=== BUTTON POSITIONING ISSUES ===

From fullscreen.css lines 596-611:
- Undo button: top: 68px; right: 12px
- Redo button: top: 120px; right: 12px
- Erase button: top: 172px; right: 12px

On 320px wide phone with padding:
- Container has: padding: 24px on sides
- Available width: 320 - 48 = 272px
- Button width: 44px
- Button position right: 12px means left edge = 320 - 12 - 44 = 264px
- In fullscreen mode with fixed pitch wrapper:
  - Buttons positioned relative to .flab-field
  - .flab-field IS the fullscreen element
  - Buttons at right: 12px go outside visible area

At max-width: 640px breakpoint, only:
- Undo: top 60px
- Redo: top 108px
- Erase: top 156px

NO changes for 480px, 359px, or smaller phones!

=== KEYBOARD OVERLAP ===

From fullscreen.css line 725:
bottom: clamp(32px, 5vh, 80px)

On 667px phone:
- 5vh = 33px (very small)
- Mobile keyboard = 250-300px tall
- Controls positioned at: 33px from bottom
- Keyboard appears and hides controls completely
- NO detection of keyboard appearance
- NO adjustment when keyboard shows/hides

=== SAFE AREA INSETS MISSING ===

Current button positioning:
.flab-undo-redo-btn { top: 12px; right: 12px; }
.flab-theme-btn-corner { top: 12px; left: 12px; }

Missing safe area handling:
- iPhone with notch: safe-area-inset-top = 44-47px
- Button at top: 12px goes UNDER notch
- iPhone bottom: safe-area-inset-bottom = 34px (home indicator)
- Controls at bottom: 80px may still overlap home indicator

Should be:
right: max(12px, env(safe-area-inset-right))
top: max(12px, env(safe-area-inset-top))
bottom: max(80px, env(safe-area-inset-bottom))

=== NATIVE FULLSCREEN API FAILURES ===

iOS Safari: No support for requestFullscreen on document element
- Silently fails (no error thrown)
- Only supports fullscreen on <video> elements
- Game over - can't enter native fullscreen

iOS Chrome: Uses webkit prefix but doesn't actually support
- Returns false immediately
- Fallback to CSS fullscreen (which has all above issues)

Android Chrome: Supports but needs user gesture
- If called from setTimeout, fails
- Requires direct user interaction
- Current code doesn't validate gesture context

=== FORCED LANDSCAPE ORIENTATION ===

From orientation.js line 49:
setOrientation('landscape');  // Forces landscape!

Problems:
- Mobile phones can be held in portrait or landscape
- Code prevents portrait orientation
- No device rotation handling
- Portrait CSS is disabled (see field.css:101)
- No portrait pitch SVG assets
- User frustrated - can only view in landscape

=== VIEWPORT META TAG ===

Current: <meta name="viewport" content="width=device-width, initial-scale=1" />

Missing directives:
- viewport-fit=cover (handles notch/safe areas)
- user-scalable=yes (accessibility - user can zoom)
- maximum-scale=5 (reasonable zoom limit)

Should be:
<meta name="viewport" 
  content="width=device-width,
           initial-scale=1,
           viewport-fit=cover,
           user-scalable=yes,
           maximum-scale=5" />
